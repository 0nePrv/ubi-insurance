# ADR-0001: Монорепозиторий и структура Gradle

**Status:** Accepted
**Date:** 2026-09-11

## Context

Семь сервисов на Java и Kotlin, общие protobuf-контракты, общие технические библиотеки.
Разработчик один, важны скорость рефакторинга через границы сервисов и единые версии зависимостей.

## Decision

Один репозиторий, одна Gradle-сборка:

- `build-logic` — included build с convention-плагинами (`ubi.java-conventions`, `ubi.java-library`,
  `ubi.spring-boot-app`, `ubi.kotlin-spring-app`). Модули описывают только то, чем отличаются.
- `gradle/libs.versions.toml` — единственный источник версий. Всё, что управляется Spring Boot BOM, не дублируется.
- `platform/*` — `java-platform` модули вместо плагина `io.spring.dependency-management`: нативный механизм Gradle,
  работает одинаково для Java и Kotlin, виден в `dependencies`/`dependencyInsight`.
- `contracts` — protobuf для gRPC и событий Kafka. Единственное, что сервисы разделяют на уровне кода.
- `libs/*` — только технический код (outbox, inbox, тестовая инфраструктура). Доменного кода там нет и не будет:
  общая доменная библиотека — прямой путь к распределённому монолиту.
- Внутри сервиса — гексагональная структура `domain / application / adapter`, правила проверяет ArchUnit.

## Options Considered

### Option A: Polyrepo (репозиторий на сервис)
**Pros:** честная независимость деплоя и версий. **Cons:** для одного разработчика — постоянная синхронизация
контрактов и версий, изменение через несколько сервисов = несколько PR. Отвергнуто.

### Option B: buildSrc вместо included build
**Pros:** проще старт. **Cons:** любое изменение в buildSrc инвалидирует конфигурацию всей сборки. Отвергнуто.

## Consequences

- Легче: сквозной рефакторинг, одна команда `./gradlew build`, единые версии.
- Сложнее: соблазн «просто импортировать класс из соседнего сервиса». Защита — сервисы не зависят друг от друга
  в Gradle вообще; общаются только через `contracts`.
- JPA-аннотации в домене claims/billing разрешены (прагматичный компромисс против двойного маппинга);
  в policy домен полностью чистый, так как хранится событиями.
